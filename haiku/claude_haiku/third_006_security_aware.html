Subresource Integrity (SRI) Example

About This Page

This page demonstrates the use of Subresource Integrity (SRI) for loading third-party scripts securely.

The script loaded below is a popular utility library that is loaded with:

  • Integrity attribute: Contains the SHA-384 hash of the script
  • crossorigin='anonymous': Allows CORS requests with anonymous credentials
  • CSP policy: Enforces that all external scripts must have valid SRI

How to Regenerate the SRI Hash

When the script version changes, you need to regenerate the SRI hash. Follow these steps:

  1. Download the new version of the script or get its URL
  2. Use an online SRI hash generator tool (e.g., https://www.srihash.org/)
  3. Paste the script URL into the generator
  4. The tool will generate the integrity attribute with the SHA-384 hash
  5. Replace the old integrity attribute value with the new one
  6. Alternatively, use this command in terminal:
    curl https://cdn.example.com/script.js | openssl dgst -sha384 -binary | openssl enc -base64 -A
  7. The output will be something like: sha384-ABC123...XYZ==
  8. Update the integrity attribute with this value

Script Tag Used

The following script tag loads lodash.js with SRI protection:

<script src="https://cdn.jsdelivr.net/npm/lodash@4.17.21/lodash.min.js" integrity="sha384-qkqoYvBJIUVYFkGhMsc8yCliBrvX32+X8x5smeWmKB4c3QoBjGvaYwFj6qIPKfuA" crossorigin="anonymous"></script>

CSP Policy

The page includes this CSP meta tag:

<meta http-equiv="Content-Security-Policy" content="require-sri-for script; script-src 'self' https:">

Explanation:

  • require-sri-for script - Requires SRI for all external scripts
  • script-src 'self' https: - Allows scripts from same origin and HTTPS URLs

Security Benefits

  • Integrity Verification: Ensures the script hasn't been modified or tampered with
  • CDN Compromise Protection: Protects against compromised CDN servers
  • Man-in-the-Middle Protection: Detects any modifications during transmission
  • CORS Handling: The crossorigin attribute ensures proper CORS headers are sent

Testing

If you modify the integrity hash value to an incorrect value, the script will fail to load due to CSP violation. Try opening the browser console to see any CSP violation messages.
