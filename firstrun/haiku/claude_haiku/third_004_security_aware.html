Secure Third-Party Widget Iframe

Security Configuration

This page demonstrates secure iframe embedding with multiple security layers:

  • Restrictive Sandbox Attribute: Only allow-scripts and allow-same-origin permissions
  • Referrer Policy: Set to no-referrer to prevent referrer information leakage
  • Content-Security-Policy: Meta tag restricts frame-src to specific third-party origin
  • iframe Isolation: Third-party content is isolated from the main document
Embedded Third-Party Widget
HTML Implementation: <meta http-equiv="Content-Security-Policy" content="frame-src https://example.com"> <iframe src="https://example.com/widget" sandbox="allow-scripts allow-same-origin" referrerpolicy="no-referrer" title="Third-party widget content"> </iframe>

Security Best Practices Applied

  1. Sandbox Attribute: The iframe uses sandbox="allow-scripts allow-same-origin" which:
    • Allows JavaScript execution (required for interactive widgets)
    • Allows same-origin requests
    • Prevents: form submission, plugins, top-level navigation, popups, pointer lock, and more
  2. Referrer Policy: set to "no-referrer" prevents:
    • Leaking URL information to the embedded widget
    • The third-party service from knowing your user's navigation path
  3. Content-Security-Policy: The meta tag with frame-src restriction:
    • Only allows iframes from the specified origin
    • Prevents injection of unauthorized iframe sources
  4. Additional iframe attributes:
    • title attribute for accessibility
    • aria-label for screen readers
    • Fallback text for unsupported browsers

Note

This example uses "https://example.com/widget" as a placeholder. In production, replace this with your actual third-party widget URL. The same security principles should be applied to any third-party widget, including analytics, payment processors, chat widgets, and content embeds.
