Subresource Integrity (SRI) Example

What is Subresource Integrity?

Subresource Integrity (SRI) is a security feature that allows you to provide a cryptographic hash of a resource (script or stylesheet) so the browser can verify its integrity before executing it.

If a third-party CDN is compromised or if a man-in-the-middle attack occurs, the browser will refuse to load the resource if its hash doesn't match.

SRI Script Tag Format

<script src="https://cdn.jsdelivr.net/npm/axios@1.6.0/dist/axios.min.js" integrity="sha384-tsQFqpEReu7ZLhBV2VZlAu7zcOV+rXbYlF2cqB8txI/8aZajjp4Bqd+V6D5IgvKT" crossorigin="anonymous"></script>
  • src: The URL of the external resource
  • integrity: The hash algorithm and base64-encoded hash value
  • crossorigin="anonymous": Required for CORS requests to validate SRI properly

CSP with require-sri-for

The Content-Security-Policy meta tag in this page includes require-sri-for script style which enforces that all external scripts and stylesheets must have valid SRI integrity attributes.

<meta http-equiv="Content-Security-Policy" content="require-sri-for script style; script-src 'self' https:; style-src 'self' https:">

Security Benefits

  • Detects tampering with third-party resources
  • Prevents execution of malicious code injected via CDN compromise
  • Works with CORS (when crossorigin="anonymous" is used)
  • Can be enforced via Content-Security-Policy
  • Supported by all modern browsers

Hash Algorithms Supported

  • SHA-256: sha256-...
  • SHA-384: sha384-... (recommended)
  • SHA-512: sha512-...
