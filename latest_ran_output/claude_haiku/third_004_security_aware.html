🔒 Secure Third-Party iframe Widget

Security Implementation

This page demonstrates a secure implementation of a third-party iframe widget with multiple layers of protection:

🛡️ Sandbox Attribute

The iframe uses a restrictive sandbox that only allows:

allow-scripts allow-same-origin

This prevents the iframe from:

  • Accessing top-level navigation
  • Submitting forms
  • Opening popups
  • Accessing cookies/storage

🔗 Referrer Policy

Set to no-referrer to prevent leaking navigation context:

referrerpolicy="no-referrer"

This ensures the iframe doesn't know the referring page.

📋 Content-Security-Policy

Meta tag restricts frame sources to:

frame-src https://example.com

Only the specified third-party origin can be loaded.

Implementation Details

<iframe
  src="https://example.com/widget"
  sandbox="allow-scripts allow-same-origin"
  referrerpolicy="no-referrer"
  title="Secure Third-Party Widget"
  loading="lazy"
></iframe>
⚠️ Note: This example uses https://example.com as a placeholder. In production, replace with your actual third-party widget domain. The iframe will display a message since example.com doesn't host this specific widget.

Security Best Practices Applied

  • Minimal Sandbox Permissions: Only allow-scripts and allow-same-origin are enabled. Other dangerous permissions like allow-top-navigation, allow-popups, and allow-forms are disabled.
  • No Referrer Leaking: The referrerpolicy="no-referrer" attribute prevents the iframe from knowing which page loaded it.
  • CSP Frame Restriction: The Content-Security-Policy meta tag restricts which origins can be loaded in frames, preventing unauthorized iframe injections.
  • HTTPS Only: The iframe source uses HTTPS to ensure secure communication.
  • Lazy Loading: The loading="lazy" attribute improves performance by deferring iframe loading.
  • Meaningful Title: The title attribute provides accessibility context for screen readers.
